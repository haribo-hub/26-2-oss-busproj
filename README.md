# 6002번 광역버스 만석 위험 안내

숭실대학교 2026-2 오픈소스기초설계 02분반 10팀 프로젝트다. 목표는 한 방향·한 목표 정류장의 도착 시 API 잔여 좌석이 0석일 위험을 안내하는 것이다. 개인의 실제 탑승 성공을 예측하지 않는다.

## 현재 상태

2026-11-22 재조회에서 버스노선·버스위치정보·버스도착정보 API가 모두 정상 응답했다. 6002번 동탄2차고지 → 신분당선강남역(중) 방면의 목표 정류장은 예솔초.호반2차.대원2차다. 도착정보와 위치정보에서 접근 차량 두 대를 연결했고, 그중 한 대가 11번에서 12번 정류장으로 진행하는 것을 확인했다. 이번 표본에서 목표 도착 순간의 좌석은 관측되지 않아 평가용 정답은 0건이다.

## 시작하기

[API 조회 도구](src/probe_api.py)는 Python 3의 표준 라이브러리를 사용한다. 저장소 루트에서 아래 명령으로 API 키 없이 오프라인 테스트를 실행할 수 있다.

~~~bash
python3 -m unittest discover -s tests -v
~~~

## 실제 API 조회

저장소 루트에 `.env`를 만들고 본인의 키를 입력한다. 환경변수 `GBIS_SERVICE_KEY`가 있으면 그 값을 먼저 사용한다. 키는 채팅이나 Git에 넣지 않는다. 아래 조회 명령은 저장소 루트에서 실행한다.

~~~dotenv
GBIS_SERVICE_KEY=
~~~

확인한 값은 노선 ID `233000136`, 목표 정류장 ID `233002421`, 목표 순번 `13`, 회차 순번 `39`다. 아래 명령으로 노선과 정류장을 다시 조회하고 차량 위치와 도착정보를 각각 저장할 수 있다.

~~~bash
mkdir -p data/raw
python3 -m src.probe_api routes 6002 --output data/raw/routes_6002.json
python3 -m src.probe_api stations 233000136 --output data/raw/stations_6002.json
python3 -m src.probe_api locations 233000136 --output data/raw/locations_6002.json
python3 -m src.probe_api arrivals 233002421 --output data/raw/arrivals_6002.json
~~~

저장된 payload의 결과코드와 실제 노선·기점·종점을 확인한다. 실제 routeId를 확인한 다음 stations 명령으로 정류장 순서와 방향을 확인하고, locations 명령으로 좌석·위치 응답을 확인한다. arrivals 명령에는 실제 stationId를 사용한다. 제안서 그림의 정류소 표시번호 55340을 stationId로 대입하지 않는다.

조회 종류는 `routes`, `stations`, `locations`, `arrivals` 중 하나이며, 그다음에 노선번호 또는 해당 API ID를 입력한다. 기존 파일은 덮어쓰지 않으므로 다시 조회할 때는 새 파일명을 사용한다. 다른 폴더에서는 `src/probe_api.py`의 절대 경로로 실행할 수 있다. 기본 `.env`는 항상 저장소 루트에서 읽으며, 상대 `--output` 경로는 명령을 실행한 폴더를 기준으로 해석한다.

~~~bash
python3 -m src.probe_api --help
~~~

JSON 저장 성공은 API 업무 결과의 성공이나 도착 정답 검증을 의미하지 않는다. 도구는 반복 수집, 운행 연결, 학습, 만석 판정을 하지 않는다. 수집 주기와 호출 한도는 서비스별 승인 내역을 확인한 뒤 정한다.

## 자료 공유 범위

강의자료, 제출 제안서, 내부 개발 착수안은 팀이 승인한 공유 경로에서 확인한다.

.env, 원본 강의자료·제안서, data/raw/는 기본 Git 제외 대상이다. .gitignore는 이미 추적 중인 파일을 제거하지 않는다. 공개 허락이 필요한 강의자료와 API 데이터의 이용 조건은 각각 확인한다. API 데이터의 공개 가능성을 강의자료의 공개 허락으로 해석하지 않는다.

개발 기능은 수집·운행 연결·도착 정답·기준선·간단한 모델·최소 안내·비교 실험에 집중한다. Apache, MariaDB, Docker, 클라우드 배포, 여러 노선과 복잡한 프론트엔드는 이번 필수 범위에서 제외한다.
